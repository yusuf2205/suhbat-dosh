# Suhbat-dosh — собственный мессенджер

Веб-мессенджер (ПК и телефон, устанавливается как PWA) с сервером на вашем NAS. Сообщения и файлы хранятся только у вас: SQLite-файл и каталог с вложениями в `./data`.

Интерфейс: русский и узбекский, светлая/тёмная тема.

## Стек и схема

```
браузер / PWA ──HTTPS──► [Caddy, опционально] ──► Node.js 24 (Express 5 + ws)
                                                     ├─ REST  /api/*
                                                     ├─ WebSocket /ws  (события реального времени)
                                                     └─ SQLite (node:sqlite) + файлы на диске  → ./data
```

| Каталог | Назначение |
|---|---|
| `server/` | бэкенд: `api.js` (маршруты), `service.js` (модель/сериализация), `realtime.js` (WS), `files.js` (загрузки), `db.js` + `migrations/*.sql` |
| `shared/contracts.js` | общие контракты: лимиты, роли, типы событий (используются и сервером, и клиентом) |
| `web/` | клиент без сборки: ES-модули, `sw.js`, `manifest.webmanifest` |
| `scripts/` | резервное копирование и проверка восстановления |
| `test/` | e2e-тесты сервера |

Нет внешних зависимостей, кроме `express` и `ws`; БД встроена в Node.

## Локальный запуск

Нужен Node.js ≥ 24.

```bash
npm install
npm start                # http://localhost:3000
npm test                 # e2e-сценарии сервера (поднимает свой экземпляр)
```

По умолчанию (`NODE_ENV` не production) включён тестовый режим кода: код подтверждения показывается прямо на экране входа. В production этот режим **не запускается** — сервер завершится с ошибкой.

## Установка на NAS (Docker)

1. Скопируйте проект на NAS (например, в `/volume1/docker/suhbat`).
2. `cp .env.example .env`, затем в `.env`:
   - `APP_SECRET` — случайная строка ≥ 32 символов (команда генерации есть в файле);
   - `OTP_MODE` — `log` (код читает администратор в логе контейнера) или `webhook` (ваш SMS-шлюз);
   - при необходимости `BIND_ADDRESS=0.0.0.0` для доступа из локальной сети.
3. `docker compose up -d --build`
4. Проверка: `curl http://<nas>:3000/healthz` → `{"status":"ok"}`; статус контейнера `healthy`.
5. **HTTPS.** Вариант А — профиль Caddy: в `.env` задайте `DOMAIN`, откройте порты 80/443 на роутере и выполните `docker compose --profile https up -d`. Вариант Б — встроенный reverse proxy NAS (Synology: «Панель управления → Портал входа → Обратный прокси», с включённой поддержкой WebSocket) на `127.0.0.1:3000`; в этом случае поставьте `TRUST_PROXY=true`.
6. Диск `data/` шифруйте средствами NAS (шифрование тома/общей папки): приложение само не шифрует файлы базы.

### Обновление
```bash
git pull            # или замените файлы проекта
docker compose up -d --build
```
Миграции БД применяются автоматически при старте. Перед обновлением сделайте резервную копию.

### Резервное копирование и восстановление
```bash
docker compose exec suhbat node scripts/backup.mjs          # снимок БД + файлы → ./backups/suhbat-<время>
docker compose exec suhbat node scripts/restore-check.mjs   # проверка последней копии (integrity_check, файлы, FK)
```
Скрипт `backup.mjs` проверяет копию сам и завершается с ошибкой, если она неполная. Настройте на NAS расписание (Task Scheduler / cron) и отправку `./backups` на другой носитель (Hyper Backup и т. п.) — копия на том же диске не защищает от его отказа.

Восстановление: остановите контейнер, замените содержимое `./data` на `suhbat.db` и `files/` из копии, запустите снова.

## Приложения (Windows, Linux, macOS, Android, iOS)

Клиент один и тот же: оболочки только хранят адрес вашего сервера и открывают его интерфейс, поэтому бизнес-логика и API не дублируются. При первом запуске приложение просит адрес сервера (например, `https://suhbat-dosh.uz`) и проверяет `/healthz`. Сменить сервер: Windows/Linux/macOS — меню Suhbat-dosh → «Сменить сервер…» (Ctrl+Shift+S); Android/iOS — Настройки → Сервер.

| Платформа | Исходники | Как собрать | Как запустить |
|---|---|---|---|
| Windows | `apps/desktop` (Electron) | `cd apps/desktop && npm install && npm run dist:win` → `dist/Suhbat-dosh Setup 0.1.0.exe`, `dist/Suhbat-dosh-0.1.0-win.zip` | установщик, либо распаковать zip и открыть `Suhbat-dosh.exe` |
| Linux | `apps/desktop` | на Linux: `npm run dist:linux` (AppImage, deb); на Windows: `npm run dist:linux:portable` → `dist/suhbat-desktop-0.1.0.tar.gz` | `chmod +x Suhbat-dosh-*.AppImage && ./Suhbat-dosh-*.AppImage`, `sudo dpkg -i *.deb`, либо распаковать tar.gz и запустить `suhbat-desktop` |
| macOS | `apps/desktop` | **только на macOS**: `npm run dist:mac` (dmg, zip) | открыть dmg; без подписи — ПКМ → «Открыть» |
| Android | `apps/mobile` (Capacitor) | `cd apps/mobile && npm install && npx cap sync android && cd android && gradlew.bat assembleDebug` → `app/build/outputs/apk/debug/app-debug.apk` | `adb install -r app-debug.apk` или скопировать APK на телефон |

Сборочная заметка: если системный DNS не резолвит `github.com`, запускайте сборочные команды с `NODE_OPTIONS="--require <путь>/scripts/dnsfix.cjs"` — скрипт использует публичный DNS только для этого процесса и ничего не меняет в системе.

## Раскладки и управление

- **Телефон (≤ 600 px):** список и чат — отдельные экраны, нижняя панель (Чаты / Новый / Настройки), свайп от левого края — назад, безопасные области экрана, чат поднимается над экранной клавиатурой.
- **Планшет (601–1279 px):** две панели, портрет и ландшафт.
- **Компьютер:** список + чат; от 1280 px — третья панель с информацией о чате (кнопка ⓘ или Ctrl+I); от 1800 px колонки шире.
- **Узкое окно:** при сужении до 600 px раскладка сама переходит в телефонную, без горизонтальной прокрутки.
- **Клавиатура и мышь:** Ctrl/⌘+K поиск, Ctrl/⌘+, настройки, Alt+↑/↓ следующий чат, Esc закрыть, ↑ в пустом поле — править своё последнее сообщение, ПКМ по чату и по сообщению — контекстное меню.
- **Текст:** размер 90–150 % в настройках; вёрстка в rem; светлая/тёмная тема следует системе.

## Что реализовано

**Аккаунт:** вход и регистрация по номеру + одноразовый код (хранится только HMAC, срок 5 мин, 5 попыток, лимиты по IP и номеру); профиль (имя, фото, username, статус, описание); поиск по username/имени/точному номеру; приватность фото / статуса / времени посещения (все · контакты · никто); блокировка; список активных сессий и их завершение.

**Личные чаты:** реальное время (WebSocket); статусы отправлено → доставлено → прочитано; редактирование и удаление своих сообщений; ответ, пересылка, реакции, закрепление; «печатает»; последнее посещение; поиск по сообщениям (везде и внутри чата) с переходом к найденному; черновики (хранятся на сервере и синхронизируются между устройствами); счётчик непрочитанных и разделитель «Новые сообщения»; пагинация истории.

**Файлы:** изображения, видео, аудио, документы; предпросмотр перед отправкой; лимит размера; голосовые сообщения (запись, прослушивание и удаление до отправки).

**Группы и каналы:** создание; приглашение по ссылке (с возможностью сбросить); роли владелец / администратор / участник; запрет писать отдельному участнику; удаление и блокировка (с разблокировкой); закреп; описание; отключение звука; в канале пишут только администраторы; ограничение частоты сообщений (защита от спама).

**Устройства и сеть:** несколько устройств одного аккаунта получают события одновременно; при потере связи текстовые сообщения попадают в очередь (`localStorage`) и отправляются после восстановления, повтор идемпотентен по `client_id`; индикатор состояния подключения и числа сообщений в очереди; после переподключения клиент подтягивает пропущенное.

**Безопасность:** права проверяются на сервере для каждого чата, сообщения и файла (чужие чаты отвечают 404); файлы получают случайный 128-битный идентификатор и отдаются только участникам; тип определяется по содержимому, а не по заявленному клиентом, неопознанное отдаётся как `attachment` с `nosniff` и `CSP: sandbox`, исполняемые расширения отклоняются; Origin-проверка + `SameSite=Strict` cookie; CSP без inline-скриптов; в логах нет текстов сообщений, номеров, cookie и токенов (код входа пишется только в режиме `OTP_MODE=log`, он существует именно для этого).

## Известные ограничения

- **Сквозного шифрования нет.** Защита — TLS при передаче и права доступа на сервере; администратор сервера технически видит переписку. Чаты нигде не названы «зашифрованными».
- **Нет Web Push.** Уведомления (звук и системные) работают, пока вкладка/PWA открыта или свёрнута. Для уведомлений при закрытом приложении нужны VAPID-ключи и push-обработчик в `sw.js`.
- **iOS и macOS не собраны** в этой среде (нужен macOS); Android — debug-APK, Windows — неподписанный установщик (см. «Статус платформ»).
- Офлайн-очередь покрывает **текст**; вложения и голосовые требуют соединения.
- Запись голоса в автоматических тестах проверена только на стороне сервера; кнопка записи в браузере вручную не прогонялась.
- Docker-образ и `docker-compose.yml` написаны, но **не собирались в этой среде** (демон Docker был остановлен) — проверьте первый запуск на NAS.
- Нет антивирусной проверки вложений (рекомендуется ClamAV как следующий шаг), нет аватарок у групп, нет удаления/очистки личного чата, нет своего SMS-провайдера «из коробки» (только webhook-адаптер).
- Ограничитель частоты хранится в памяти процесса — рассчитан на один экземпляр сервера. SQLite подходит для семьи/команды; для крупной нагрузки нужен переход на PostgreSQL.
- Поиск сообщений — `LIKE` по тексту (без полнотекстового индекса и морфологии).
- Статус «доставлено» означает, что у получателя был открыт сокет; в группах «прочитано» показывается, когда прочитал хотя бы один участник.
- «Восстановление доступа» = повторный вход по номеру и коду; потерянные устройства завершаются в настройках → «Активные сессии». Смена номера не реализована.

## Вход через Telegram-бота

1. В Telegram откройте `@BotFather` → `/newbot` → имя и username бота (должен заканчиваться на `bot`) → получите токен.
2. На NAS: `cd /home/Joseph/docker/suhbat && sh scripts/set-telegram-token.sh` — токен вводится скрытно, записывается в `.env` (права 600), контейнер пересоздаётся. Токен не нужно отправлять в чат.
3. В приложении на экране входа появится «Войти через Telegram»: открывается бот → «Запустить» → «Поделиться номером» (первый раз; Telegram сам подтверждает, что номер ваш) → «Это я».
4. Подтверждение показывает устройство и IP, с которых начат вход, — защита от входа по чужой ссылке. Токены одноразовые, живут 5 минут и хранятся только в виде хеша.

Бот работает через long polling (исходящие соединения), публичный адрес и открытые порты не нужны. Вход по номеру и коду остаётся запасным; отключить: `OTP_MODE=off` в `.env`. Суперадмин определяется по номеру (`SUPERADMIN_PHONES` или `scripts/make-admin.mjs`), в том числе при регистрации через Telegram.

## Версия 0.2

**Оформление:** логотип в новом стиле (жёлтый фон, «лицо» с речевым пузырём), интерфейс в фиолетово-синей гамме по макету ChatWave: белые входящие и залитые исходящие пузыри, полоса «недавние», анимированные кнопки звонков.

**Обновления без переустановки** (Настройки → «Обновления» → «Проверить обновление»):
- *Интерфейс* отдаёт сам сервер: после обновления сервера открытые клиенты видят «Доступна новая версия» и обновляются по кнопке (проверка при подключении, раз в 10 минут и при возврате в окно).
- *Windows (установщик) и Linux AppImage* обновляются сами через `electron-updater`: файлы `latest.yml`, `*.exe`, `*.blockmap` лежат в `downloads/` на вашем сервере (`/downloads/`). Скачивание проверяется по sha512. Установка выполняется при перезапуске.
- *Android*: приложение находит более новый APK на вашем сервере и предлагает скачать; установку поверх старой версии подтверждает Android (самостоятельно, без подтверждения, это не разрешено системой).
- *macOS/iOS*: обновления потребуют подписи и магазина/профиля распространения.

**Выпуск новой версии:** собрать приложения (`npm run dist:win` и т. д.), скопировать в `downloads/` на сервере `latest.yml`, `*.exe`, `*.blockmap`, `*.apk` — **`latest.yml` последним**.

**Просмотр медиа и файлов:** встроенный просмотрщик поверх чата (фото: миниатюра → оригинал, масштаб колесом/жестами, соседние фото, полный экран; видео: потоковая передача с перемоткой по HTTP Range, обложка, индикатор буферизации, понятная ошибка; PDF: встроенный просмотр, постранично; остальное — скачать). Миниатюры и обложки создаются на устройстве отправителя при загрузке. Кэш фото на устройстве: до 300 МБ / 30 дней с автоочисткой и кнопкой «Очистить кэш» в настройках. Файлы отдаются только участникам чата, постоянных публичных ссылок нет. Назад в чат — на то же место прокрутки; системная кнопка «Назад» закрывает просмотрщик, а не чат. Панель «Медиа и файлы» — в меню чата.
Ограничения: адаптивного перекодирования видео (разные качества) нет — только потоковая отдача оригинала; миниатюры для форматов, которые браузер не декодирует (например HEIC), не создаются.

**Звонки:** подробности, оценка NAS и план TURN/SFU — в [docs/CALLS.md](docs/CALLS.md).

**Realtime:** сообщения, правки, удаления, реакции, прочтение, «печатает», присутствие, состав чатов, закрепления, звонки и **изменения профиля** (имя, фото, статус, приватность) доставляются сразу, в том числе на другие ваши устройства.
